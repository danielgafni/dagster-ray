# dagster-ray Dagger module

Runs all of CI as Dagger checks: ruff, basedpyright, the docs build and the test suite against KubeRay in k3s. The GitHub `CI` workflow runs `wait-for-cloud-checks`, which waits for their Dagger Cloud statuses with `typesafe-ai/daggerverse/github`.

## Layout

- `../dagger.toml`: the workspace. Installs the Python SDK and this module as the entrypoint.
- `modules/dagster-ray-dev/src/dagster_ray_dev/`:
  - `main.py`: `DagsterRayDev`, the entrypoint object. Holds the `ruff-check`, `ruff-format`, `typecheck` and `build-docs` checks and the `gen-docs` generator.
  - `compatibility.py`: renders `docs/compatibility_matrix.md` from `pyproject.toml` and `test-matrix.toml` for `gen-docs`. The `dagster-ray-dev/stale` check fails when the page is out of date.
  - `dev_env.py`: the repository with its dependencies installed, for `typecheck` and `build-docs`.
  - `image.py`: `Image` pins Ray and Dagster for one Python version, builds with `typesafe-ai/daggerverse/uv`. `dagger-pytest-otel` comes from the `dev` group.
  - `registry.py`: the registry service images are pushed to and k3s pulls from.
  - `kuberay.py`: `KuberayCluster` is k3s (`marcosnils/daggerverse/k3s`) with the KubeRay operator, parametrized by the KubeRay and Kubernetes versions only.
  - `test_job.py`: `TestJob` is one matrix entry. `run-core` runs the tests outside `tests/kuberay`, `run-kuberay` runs `tests/kuberay` against a cluster in its own namespace, and `run` does both concurrently.
  - `test-matrix.toml`: the Kubernetes, Python, Ray, Dagster and KubeRay versions under test.
  - `test_matrix.py`: adds the test checks to `DagsterRayDev` from `test-matrix.toml`.
  - `matrix.py`: expands `test-matrix.toml`.
- `modules/dagster-ray-dev/sdk/`, `clients/`: generated by `dagger generate`.

## Test matrix

`test_matrix.py` reads `test-matrix.toml` at import and adds one check per entry to `DagsterRayDev`, so Dagger Cloud runs each on its own engine. `test-core-*` checks run the tests outside `tests/kuberay`, one per Python, Ray and Dagster combination. `test-kuberay*` checks run `tests/kuberay` against their own k3s cluster. Run `dagger generate` after editing the TOML.

The TOML expands to the latest versions, the oldest versions, and each other version with the latest of the rest, minus `exclude` entries. Python, Ray and Dagster variations go to the KubeRay version with the fewest jobs.

## Commands

```bash
dagger check                                           # everything CI runs
dagger check -l                                        # list checks
dagger check test-kubernetes-client                     # JSON Patch across Kubernetes Python client versions
dagger check 'test-core-*'                             # the core tests only
dagger call test --python-version 3.13 --ray-version 2.58.0
dagger generate                                        # after changing functions or dependencies
```
